02 / THE PIPELINE

A small system with an inspectable trail.

1

Collect

100 app seeds → bounded concurrent retrieval of official docs. Cache text, timestamps, redirects and content hashes.

2

Extract

Keyword baseline produces candidates. AI-assisted review separates real product claims from navigation and examples.

3

Challenge

Fetch corrected sources. Validate citations and exact quotes. Abstain when support is missing; preserve changes.

4

Decide

Cluster auth and access patterns. Flag conditional builds and outreach. Score only completed human checks.

What ran, what is optional, and how to reproduce

The optional model mode performs extraction, a second model critique, and deterministic quote validation. Composio SDK search discovery is an optional adapter; it is not required to wrap an API as an MCP tool.

python -m agent.pipeline --workers 6
python -m agent.review --apply
python -m agent.pipeline --analyze-only
python -m http.server 8000 --directory site

With an OpenAI key configured: python -m agent.pipeline --mode ai. With a Composio key: install requirements-composio.txt and add --composio. These modes have separate run records. No paid customer accounts or production API calls were used.

What I would do next

Start with a read-only tool for a clearly documented API, prove credential onboarding, then expand the surface. Use outreach for explicit commercial or partner gates. Revisit unknown access and MCP claims with browser retrieval and a human sample before treating the shortlist as production-ready.

Limits: This is a time-boxed documentation assessment. No credentials were issued for customer apps, API calls were not tested, public docs can change, and “unknown MCP” means no confirmed evidence in the retrieved set—not that no server exists. Some developer access decisions need multiple conditions; the detailed caveat matters more than the single table label.
